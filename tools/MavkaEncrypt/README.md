# Демонстраційна перевірка шифрування файлів

Інструмент `MavkaEncrypt` містить перевірку формату
`MAVKA_KEY_PACKAGE_V1` **на синтетичних випадкових ключах**.
Це засіб тестування шифрування, а не автоматична видача робочих
облікових ключів і не реалізація настільної синхронізації.

## Windows 11: тестова утиліта без інсталяції .NET

1. У GitHub Actions для цієї тестової гілки знайти останню **успішну**
   збірку та артефакт
   `Mavka-SYNTHETIC-Key-Package-Test-Tool-Windows`.
2. Розпакувати у локальну папку `MavkaEncrypt.exe`.
3. Використовувати **лише окрему тестову версію** застосунку
   `ua.mavka.mobile.preview` з вигаданими даними. Профіль
   у тестовій версії має зберегтися, щоб сформувався її Client ID.
   ID не надсилати в чат, не додавати у GitHub.
4. У цій окремій тестовій версії вибрати пароль тестових документів,
   бажано 12+ символів. Не використовувати пароль реальних документів.
5. Відкрити PowerShell в папці з `MavkaEncrypt.exe` та виконати:

   ```powershell
   .\MavkaEncrypt.exe demo-package "$env:USERPROFILE\Downloads\MAVKA-DEMO-KEY-PACKAGE.json"
   ```

   У консолі буде запитано Client ID тестової версії та пароль
   тестових документів. Введення пароля приховано.
   Створюється лише **один зашифрований JSON** з поколінням 1:
   поточний і майбутній випадкові ключі існують відкрито тільки
   в пам'яті процесу, одразу після пакування зануляються.
   Уже наявний файл не перезаписується.

6. Для перевірки поштового каналу використовувати **тільки
   ізольовані тестові Gmail-адреси**. Відправником має бути саме
   адреса, обрана в тестовій версії як дозволений відправник.
   Надіслати зашифрований JSON як **.json вкладення**,
   з темою `MAVKA_KEY_PACKAGE_V1`.
   Пароль у листі не повідомляти.
7. У тестовій версії відкрити `☰ → Ключ обміну →
   Оновити ключі з Gmail`. Очікується покоління `1`,
   ідентифікатори поточного та майбутнього ключів.
   Після перезапуску ці ідентифікатори мають лишитися.
8. Якщо пакет прийнято, тестовий лист може автоматично
   опинитися у Gmail Trash. Це **не** означає видалення
   локально збереженої пари ключів. Не очищати дані програми.
9. Перевірити повторний імпорт **того самого** JSON у новому
   тестовому листі: покоління та обидва ідентифікатори
   не повинні змінитися.

**Перевірка помилок:** файл із невідповідним Client ID, іншим
паролем або пошкодженим ciphertext має відхилятися. Не змінювати
тестову реальну пару ключів, щоб "виправити" помилку.

## Локальні автоматизовані перевірки

```powershell
dotnet run --project tools/MavkaEncrypt/MavkaEncrypt.csproj -- selftest
```

Self-test перевіряє створення двох випадкових 256-бітних ключів,
парольний `AES-256-GCM` пакет, коректний розбір і відхилення
невірного пароля та пошкодженого шифротексту. Сам по собі він
**не перевіряє** Gmail, Android Keystore або настільну програму.

## Інші можливості існуючого CLI

```powershell
dotnet run --project tools/MavkaEncrypt -- create-key PRIVATE.mavka-key
dotnet run --project tools/MavkaEncrypt -- encrypt PRIVATE.mavka-key input.json encrypted.json
```

Ці старі команди не є частиною тесту пакетної видачі. Не додавати
секретні файли до Git, Drive, чату або загальних каталогів.
Після завершення синтетичного тесту видалити лише тестову
копію JSON у Downloads. Не чіпати робочі ключі застосунку.

**Обмеження:** збірка Android із підписом GitHub CI може не
оновлювати раніше встановлену версію через несумісність
сертифікатів; не видаляти основну програму заради тесту.
