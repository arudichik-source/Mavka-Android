# Мавка Mobile — підсумки пристроєвого QA та сім пунктів доопрацювання

Дата: 2026-10-12. База: інтеграційна гілка через PR #28, QA #29 та PR #30. 
Робочий PR: #31; не зливати в main до перевірки реальним Android.

## Сім пунктів і межі реалізації

| № | Завдання | Стан у PR #31 |
|---|---|---|
| 1 | PDF/XLSX і ключовий обмін | **PARTIAL, NO BINARY IMPORT** — Gmail показує назви та розміри PDF/XLSX як безпечні метадані, без завантаження/архівації байтів; наявна схема імпортує лише підтримувані JSON/TXT. Системний Android picker дозволяє **лише read-only відкриття** вибраних користувачем PDF/XLSX, не є імпортом до архіву чи обміном файлами. Не підміняти затверджений механізм двох ключів парольним PDF/Excel. |
| 2 | Ручне переміщення листа в Gmail Trash | **CODE + CI PASS, DEVICE PENDING** — підтвердження, UID/UIDVALIDITY та точний From повторно перевіряються; лише Trash, без expunge. Для кешованої (можливо застарілої) копії доступна лише кнопка оновлення Gmail. |
| 3 | Кеш Gmail після перезапуску | **CODE + CI PASS, DEVICE PENDING** — AES-GCM в Android Keystore, атомарний запис у приватний каталог, обмеження розміру, binding до account/sender. RawJson не зберігати в кеші, cached previews read-only, тип картки відображати через метадані. |
| 4 | Зрозумілі помилки | **CODE, CI/DEVICE RECHECK PENDING** — тайм-аут, SocketException, SSL, Gmail Trash, файлові дії, пошкоджений AES-GCM-тег та непідтримувані вкладення; UI не показує назви класів винятків. |
| 5 | Файловий менеджер | **PARTIAL + DEVICE PENDING** — SAF read-only picker для PDF/XLSX, списки експорту, пошук, сортування, відкрити/поділитися. Кнопки видалення неактивні, якщо операція порожня. Інтегрований PDF/XLSX імпорт відсутній (див. №1). |
| 6 | Статуси в історії документів | **CODE + CI PASS, DEVICE PENDING** — збережений локальний документ більше не називається «без збереження». |
| 7 | Дизайн і навігація | **PARTIAL + DEVICE PENDING** — довгі заголовки, прокручування нового екрана з початку, підказки для кешованих повідомлень, відключення недоступних дій, висота кнопок і вкладок адаптується до масштабу шрифту. Перевірка маленьких екранів і великого шрифту на пристрої обов'язкова. |

**Невід'ємні інваріанти:**
- Жодної зміни ключового формату, алгоритму, ключових ID, ротації або встановлення ключів.
- Не змінювати підтверджене офлайн-архівування та імпорт JSON.
- Не видаляти листи Gmail без перевіреного збереження або явного підтвердження користувача.
- Збережений кеш **ніколи** не стає джерелом повторного імпорту або підтвердження.
- Не перевстановлювати існуючу програму, не видаляти Android Keystore/базу; CI APK можуть мати несумісні сертифікати підпису.

## Контрольний список для наступної пристроєвої перевірки

- [ ] Перезапуск без інтернету: видимий список листів і фільтрація; кожен запис позначений як кеш.
- [ ] Кешовані листи без нового читання Gmail **не мають** кнопки перенесення в кошик.
- [ ] Після оновлення Gmail дані відображаються як актуальні; повідомлення, які сервер переніс до кошика, відсутні.
- [ ] Зміна Gmail-акаунта або дозволеного відправника очищає кеш; історія документів та ключі незмінні.
- [ ] Невірний кеш і пошкоджений AES-GCM тег не спричиняють аварійного завершення.
- [ ] На живому листі підтвердження Trash і скасування працюють; в Gmail саме кошик, не остаточне видалення.
- [ ] Без мережі — локалізоване повідомлення, без втрати раніше завантажених листів.
- [ ] Архівний файл має текст «Збережено в ...», для звичайного листа — «Перегляд вкладення».
- [ ] Gmail показує назву й розмір вкладень PDF/XLSX як метадані, не читає байти й не видаляє лист автоматично.\n- [ ] Системний вибір PDF/XLSX відкриває зовнішній переглядач; **не** додає документ до облікового архіву.
- [ ] Порожня папка не дає запускати «Очистити папку» й «Видалити вибрані».
- [ ] Android landscape та великий шрифт: заголовки, скрол і кнопки залишаються видимими.

Автоматичний CI PASS означає успішні тести та складання APK, а не пристроєвий PASS.
