# Підписаний реліз Android — правила випуску

Поточна інтеграція: PR #33, `integration/mobile-complete-20261014`.
Релізний workflow: `.github/workflows/release-android-signed.yml`.

## Блокувальні умови

- **Ніколи не створювати новий keystore у CI**. Для оновлення встановленого `ua.mavka.mobile` має використовуватися точно та сама пара ключів, що підписала встановлену версію.
- `ApplicationVersion` (`versionCode`) нового APK повинен бути вищим, ніж в усіх установлених на цільових пристроях. Поточне значення — у `src/Mavka.Mobile/Mavka.Mobile.csproj`.
- Пакет `ua.mavka.mobile.preview` окремий, зі стабільною версією користувача його не змішувати.
- Не просити користувача видаляти застосунок або очищати дані, якщо Android повідомляє `INSTALL_FAILED_UPDATE_INCOMPATIBLE`; це часто означає інший підпис.
- Не давати релізу статусу «готовий», поки фактичне тестування Gmail/Drive, сповіщень, QR та захищених файлів на Android не пройдено.

## Захищені секрети GitHub Environment `mavka-production-release`

Налаштовує лише власник репозиторію через GitHub Environment secrets. Ніколи не надсилати значення в чат, коміт, issue чи журнал.

| Назва | Вміст |
|---|---|
| `MAVKA_ANDROID_KEYSTORE_B64` | Base64 **наявного** keystore JKS/P12 із незмінним Android release key |
| `MAVKA_ANDROID_KEYSTORE_PASSWORD` | Пароль keystore |
| `MAVKA_ANDROID_KEY_PASSWORD` | Пароль конкретного ключа підпису |
| `MAVKA_ANDROID_KEY_ALIAS` | Ім'я наявного ключа |
| `MAVKA_ANDROID_SIGNING_CERT_SHA256` | 64 hex-символи SHA-256 відбитка сертифіката саме встановленої production-версії |

Для першого випуску без попередньої production-версії ключ підпису створюється **поза CI**, резервується власником і реєструється як одна незмінна release identity. Якщо на телефонах уже встановлена версія з невідомим або тимчасовим ключем, автоматичне оновлення поверх неї гарантувати неможливо.

## Релізний конвеєр

Запускається вручну **лише з `main`** після завершення перевірок. Workflow перевіряє наявність secret-значень, збирає підписаний APK, верифікує package ID `ua.mavka.mobile`, звіряє SHA-256 сертифіката з заздалегідь затвердженим, створює SHA-256 маніфест артефакту та лише після цих перевірок публікує `Mavka-Mobile-VERIFIED-SIGNED-RELEASE`.

Це не обхід Google Play або налаштувань Android — користувач підтверджує звичайне встановлення оновлення, Android перевіряє підпис.
