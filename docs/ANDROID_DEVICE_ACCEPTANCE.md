# Протокол перевірки Мавка Mobile на Android

Статус: **заготовлено для майбутніх практичних перевірок**.
Цей документ не підтверджує, що Android-пристрій уже перевірявся.

## 1. Підготовка без ризику втрати даних

1. Не видаляти вже встановлену `ua.mavka.mobile`. Не очищати її
   сховище, не запускати `adb uninstall`, `pm clear` або factory reset.
2. У GitHub Actions використати артефакт **Mavka-Mobile-TEST-APK** із
   останнього успішного запуску робочої гілки, а не Production APK.
3. Тестовий package ID повинен бути **`ua.mavka.mobile.preview`**.
   Він має незалежну базу й окремий профіль; існуюча програма лишається.
4. Паролі тестових PDF/XLSX використовувати тільки на вигаданих даних.
   Не підміняти тестовими матеріалами реальні облікові дані.
5. Змінний підпис CI не дозволяє гарантоване оновлення навіть раніше
   встановленої preview-версії. При помилці підпису зупинити встановлення,
   **не видаляти production** і не очищати її даних.

### Windows / PowerShell 7 / Android SDK Platform-Tools

```powershell
pwsh ./tools/Inspect-Android-Apk.ps1 -ApkPath "C:\Path\To\Mavka-Mobile-TEST.apk"
pwsh ./tools/Inspect-Android-Apk.ps1 -ApkPath "C:\Path\To\Mavka-Mobile-TEST.apk" -InstallPreview
```

Скрипт перевіряє ідентифікатор пакета та підпис, дозволяє встановлювати
лише preview через `adb install -r -t`. Якщо пристрій відхиляє APK,
скрипт зупиняється й не видаляє жодних даних.

## 2. Перевірки автономного інтерфейсу

- [ ] Програма відкривається та не падає без інтернету.
- [ ] Навігація / бокове меню / повернення працюють на різних екранах.
- [ ] Довгі українські рядки, великі шрифти й поворот екрана не перекривають кнопок.
- [ ] Доступ до локально збережених документів не потребує Gmail.
- [ ] Пошук та сортування у `МаVКа файли` не спричиняє помітних затримок.
- [ ] Повідомлення про помилки читання та відкриття файлів зрозумілі.

## 3. Перевірки формату PDF/XLSX (лише вигадані документи)

- [ ] PDF із 200 довгими рядками має всі позиції й коректну пагінацію.
- [ ] Українські символи, розриви, дати, суми та табличні поля читаються.
- [ ] PDF відкривається в сумісному переглядачі лише з правильним паролем.
- [ ] Пароль не потрапляє в назву файла або журнали застосунку.
- [ ] XLSX справді відкривається Microsoft Excel за правильним паролем.
- [ ] XLSX не відкривається за неправильним паролем.
- [ ] Числові клітинки XLSX залишаються числами, не текстом.
- [ ] У стандартному файловому менеджері видно `Download/МаVКа файли/`.
- [ ] Відкрити / Поділитися / Видалити один / Видалити вибрані / Очистити папку.
- [ ] Видалення копії не видаляє внутрішнього запису.
- [ ] Помилка диска / відсутній переглядач не пошкоджує локальну базу.
- [ ] Після завершення експорту у Downloads немає незашифрованих копій.

## 4. Сумісність і оновлення

- [ ] Перевірити Android 10+ MediaStore.
- [ ] Android 8/9: SAF ще не реалізовано; відобразити відповідне обмеження.
- [ ] Перевірити Android 13/14/15 та зміну масштабу шрифтів.
- [ ] Переконатися, що production application ID і дані не змінено.
- [ ] Відновлення старих приватних SQLite даних/ключів **не перевірялося**.
- [ ] Стабільний ключ підпису відсутній; **без заміни ключа не обіцяти оновлення поверх production**.

## 5. Звіт про перевірку

Записати:
- модель пристрою та Android SDK/version;
- GitHub Actions run, commit SHA, назву artifact, package ID;
- заповнені чекбокси і точні кроки відтворення проблем;
- окремо помилки PDF, XLSX, MediaStore, навігації, автономної роботи;
- чи відновилася робота програми після виходу та повторного запуску.

**Не позначати роботу готовою лише на підставі зеленого GitHub Actions.**

## 6. Синтетичний тест першого отримання ключів (preview only)

**Передумови:** тестова збірка, ізольовані Gmail-адреси,
вигаданий профіль, порожній тестовий Inbox, окремий пароль документів.
Не використовувати службові дані чи ключі.

- [ ] Згенерувати за інструкцією
      `tools/MavkaEncrypt/README.md` лише один зашифрований
      синтетичний JSON-пакет для ID тестового профілю.
- [ ] Переконатися, що файл відсутній у відкритому вигляді
      та жоден файл .mavka-key не створювався.
- [ ] Доставити JSON з окремої дозволеної **тестової** пошти.
- [ ] Перевірити Gmail TLS та отримання листа.
- [ ] Натиснути «Оновити ключі з Gmail»: очікуються поточний
      і майбутній ID, покоління 1.
- [ ] Повністю закрити та знову відкрити тестову програму:
      обидва ID й покоління збереглися.
- [ ] Повторний імпорт того самого пакета не змінює покоління.
- [ ] Невірний пароль або пакет для іншого тестового ID відхиляється.
- [ ] Перевірити поведінку Gmail Trash після успішного читання.
- [ ] Зафіксувати лише екран стану; не публікувати паролі або
      вміст зашифрованих пакетів у журналі тестів.

Цей тест сам по собі не доводить, що реальна ГОЛОВНА МАВКА
автоматично випускає ключі. Настільна інтеграція окрема й
поки не завершена.

## 7. Ручне перенесення неприйнятих Gmail-листів у кошик

**Сценарій:** синтетичне пошкоджене шифроване вкладення та
невідомий JSON ізольованого тесту можуть залишитися у Inbox:
вони не проходять перевіреного архівування, тож автоматичне
очищення їх не переміщує. Це правильний захист від втрати даних.

- [ ] Для пошкодженого синтетичного вкладення в картці листа
      видно точну причину відхилення шифрованих даних.
- [ ] Відкрити лист → «Перемістити лист у кошик Gmail».
- [ ] «Скасувати» у підтвердженні залишає лист у вхідних.
- [ ] Підтвердити «У кошик» — лист зникає з вхідних програми
      та з'являється у кошику Gmail.
- [ ] Лист не видаляється остаточно (ніякого Gmail expunge).
- [ ] Локальні документи, Android Keystore та пара ключів
      залишаються доступними після закриття й повторного
      запуску застосунку.
- [ ] Без інтернету / з помилкою Gmail лист залишається
      у списку, а програма показує повідомлення про збій.
- [ ] Автоматичний імпорт і автоматичне перенесення в кошик
      продовжують діяти лише після перевіреного збереження.
- [ ] В історії локально збережених документів кнопка
      ручного переміщення оригіналу не показується.

Не очищати основну програму під час тестування. APK із
тимчасовим CI-підписом може не оновити попередню тестову
інсталяцію; необхідний той самий сертифікат підпису.
