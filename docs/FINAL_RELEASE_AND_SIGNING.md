# Мавка Mobile: єдиний реліз та безпечне оновлення

## Головне правило підпису

Один APK `ua.mavka.mobile` можна встановити **поверх існуючої Мавки зі
збереженням Android Keystore, SQLite, Gmail-налаштувань та приватних вкладень**
лише коли підпис нової версії збігається з підписом уже встановленої.

Якщо інсталяція QA31 (`ua.mavka.mobile.qa31`) була зроблена debug-ключем
одноразової GitHub Actions збірки, її дані НЕ мігрують автоматично в
`ua.mavka.mobile`. Змінити Android ApplicationId або підпис — не означає
безпечно оновити застосунок. **Не видаляйте QA31 заради релізу.**

## Однократне налаштування GitHub Actions

Власник репозиторію має внести **секрети GitHub Actions**:

- `MAVKA_ANDROID_KEYSTORE_B64`: Base64 вмісту постійного release-keystore,
  не відкритий ключ шифрування Мавки
- `MAVKA_ANDROID_STORE_PASSWORD`: пароль release-keystore
- `MAVKA_ANDROID_KEY_ALIAS`: alias релізного підпису
- `MAVKA_ANDROID_KEY_PASSWORD`: пароль ключа підпису
- `MAVKA_ANDROID_CERT_SHA256`: SHA-256 DER-сертифіката саме того підпису,
  який повинен мати APK (64 hex-символи)

Вміст JKS і паролі не передавайте в чат, у коміти чи як тестові вкладення.
Зберігайте офлайн резервну копію JKS і пароль у надійному сховищі.

Workflow `.github/workflows/release-android.yml`:
1. Працює лише для схваленого `main`.
2. Запускає регресійні перевірки архіву, обліку, криптографії, файлів,
   генераторів, передачі, PDF, Office та міграцій SQLite.
3. Зупиняється, якщо хоча б один секрет відсутній чи SHA-256 підпису JKS
   не відповідає затвердженому.
4. Підписує APK постійним JKS і повторно перевіряє підпис уже створеного APK.
5. Публікує **єдиний** артефакт `Mavka-Mobile-FINAL-SIGNED-APK`.

Запуск: GitHub → Actions → **Build signed final Mavka Mobile** →
**Run workflow** на `main`, тільки після успіху QA та підтвердження
відповідності існуючому підпису на телефоні.

Поки секретів немає, `build-android.yml` випускає лише CI-збірки;
їх не вважають стабільним релізом і не встановлюють поверх наявних даних.

## Формат обміну та пароль

Основний поточний/майбутній ключ AES-256-GCM і його ротація **не змінені**.
Додатковий парольний зовнішній формат `MAVKA_PASSWORD_WRAPPED_V1` з
PBKDF2-SHA256 (350000 ітерацій, випадковою сіллю) і AES-256-GCM
обгортає **вже зашифрований** `MAVKA_ENCRYPTED_V1`,
`MAVKA_ENCRYPTED_FILE_V1` або `MAVKA_FILE_PART_V1`.

Підтримується дешифрування старих AES-256 контейнерів для сумісності
зі вже перевіреними документами. Нові вихідні частини та Word із
Android вимагають налаштований пароль документів. Пакет видачі ключів
`MAVKA_KEY_PACKAGE_V1` і так має власний парольний захист.

Команди утиліти настільного відправника після видачі ключів:
`encrypt-password`, `file-parts-password`,
`drive-command-password`. Для CI можна задати
`MAVKA_DOCUMENT_PASSWORD`; не розміщувати пароль у репозиторії.

Зашифрований парольний контейнер **не те саме**, що DOCX із
вбудованим Office-паролем. Генерація DOCX із JSON накладної реалізована;
її надсилання відбувається у двошаровому контейнері без запису відкритої
копії. Окремий Office-сумісний захист DOCX ще потребує реалізації.

## Пристроєвий релізний приймальний тест

- Gmail: звичайні, повторні, пошкоджені листи та 4–50 вкладень,
  вимірювання часу першої та повторної синхронізації;
- 20 початкових позицій на дату, 8 та 7 позицій накладних,
  зміна залишку і суми пошуку, без повторного проведення;
- підтвердження, вручну та автоматично Gmail Trash, довге натискання;
- зашифровані PDF/XLSX/DOC/DOCX/PNG/JPEG/WebP, експорт лише за
  явної згоди, фото-перегляд, перезапуск посеред передачі;
- парольний шар: правильний, неправильний пароль, пошкоджений тег;
- Drive: посилання, SHA-256, HTTP Range після розриву, підміна домену;
- очищення локального обліку з двома підтвердженнями, збереження
  Gmail/Keystore/архіву;
- збереження даних після **оновлення APK з тим самим підписом**.

Ці пункти треба перевірити на фізичному Android. CI PASS свідчить лише
про програмну збірку та автоматичні тести, а не про повний E2E.

**Відкриті залежності для повноцінного релізу:** існуючий release-keystore
і SHA-256 підпису; доступ до приватного Drive через OAuth (зараз доступні
посилання, які може завантажити програма); наскрізний парсер/відправник
в ГОЛОВНІЙ МАВЦІ; реальні Android E2E з новими контейнерами.
