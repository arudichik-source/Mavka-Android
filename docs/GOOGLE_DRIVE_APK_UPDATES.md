# Оновлення Мавки Mobile через Google Drive

## Як працює

У **Налаштування → Оновлення Мавки → Оновити через Google Drive**
користувач вставляє посилання на APK (звичайне
`https://drive.google.com/file/d/FILE_ID/view`, або
`https://drive.google.com/open?id=FILE_ID`). Доступ до APK на Drive
має бути дозволений тим, хто має посилання; вхід через Google/OAuth поки
не використовується.

1. Застосунок приймає лише HTTPS-домени Google Drive/
   `googleusercontent.com`, не довільні вебсайти чи перенаправлення.
2. APK завантажується **лише в приватний кеш Android**, максимум 220 МБ,
   відновлення після обриву через HTTP Range, обмеження повторів.
3. Перевіряються ZIP, AndroidManifest.xml і classes.dex, розраховується
   SHA-256 для контрольної суми.
4. Android PackageManager перевіряє package id **ua.mavka.mobile**,
   **вищий versionCode**, **той самий SHA-256 сертифіката APK-підпису**,
   що вже встановлений на телефоні.
5. Мавка показує версії та SHA-256 і запитує явне підтвердження.
6. Системний інсталятор Android відкриває APK через тимчасовий
   **read-only content URI** з приватного кешу, перевіряє автентичність
   і питає дозволу користувача. Без системного підтвердження нічого
   не встановлюється.
7. Якщо Android вимагає «Дозволити встановлення з цього джерела»,
   Мавка переводить на системний екран дозволу. Після повернення
   користувач натискає **ту саму кнопку** (можна не вставляти посилання
   вдруге — вже завантажений APK збережений у приватному кеші).
8. Окрема кнопка видаляє **тільки тимчасово завантажений APK**;
   база, документи, Gmail і Android Keystore не чіпаються.

## Правила випуску оновлень через ГОЛОВНУ МАВКУ

- Спочатку збирають **підписаний тим самим довготривалим JKS**
  APK із більшою `ApplicationVersion`/Android `versionCode`.
- Його розміщують на Google Drive та надають співробітникам лише
  посилання. За потреби ГОЛОВНА МАВКА пересилає URL в існуючому
  шифрованому повідомленні. В автоматичному застосуванні URL
  без підтвердження користувача **не використовується**.
- **Ніколи не змінюйте підпис APK між релізами.** Android не дозволить
  оновлення іншого підпису зі збереженням приватної бази і ключів.
- Пакет старої **QA31** (`ua.mavka.mobile.qa31`) — інший пакет; оновити
  його APK `ua.mavka.mobile` з перенесенням даних неможливо.
  **Не видаляйте QA31.**
- APK на Drive не містить секретного обліку; подібний механізм
  непридатний для розповсюдження документів без окремого шифрування.
- Якщо Drive повертає HTML («Підтвердьте скачування», потрібен логін),
  це **не APK**, встановлення блокується. Для приватних Drive-файлів
  потрібна окрема інтеграція OAuth або авторизоване посилання.

## Чого немає

Не впроваджено фонове автоматичне встановлення без участі людини
(звичайному Android-застосунку це недоступно).
Немає автоматичного розсилання release-URL із ГОЛОВНОЇ МАВКИ.
Перевірка підпису в Мавці є додатковим запобіжником, Android
виконує власну остаточну перевірку APK.

Android CI тестує парсинг Google URL, підміни host, чужі пакети/
сертифікати, downgrade, перерваний Range-download та компіляцію
інтерфейсу. **Фактичне встановлення потрібно протестувати на
двох послідовних релізах, підписаних одним JKS, на фізичному Android.**
