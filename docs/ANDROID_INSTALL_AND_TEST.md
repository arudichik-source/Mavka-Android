# Мавка Mobile — безпечне встановлення й тестування

## Причина конфлікту APK
Поточна Android-програма має applicationId ua.mavka.mobile. GitHub Actions збирає APK без постійного підписного keystore. Різні запуску можуть використовувати несумісні debug-підписи, через які Android відхиляє оновлення.

**Не видаляй установлену Мавку.** Це може стерти локальну SQLite-базу і захищені налаштування Gmail. Поки немає перевіреного експорту, не очищуй її дані.

## Окремий TEST APK
У збірці GitHub Actions є два артефакти:
- Mavka-Mobile-APK — звичайна програма ua.mavka.mobile; без старого сертифіката не замінить старий APK.
- Mavka-Mobile-TEST-APK — тестовий ua.mavka.mobile.preview, який встановлюється **поруч** із основним додатком.

Для тестування скачай саме Mavka-Mobile-TEST-APK, розпакуй ZIP і встанови його, не видаляючи основний застосунок. Новий TEST матиме окрему порожню базу й налаштування; він НЕ імпортує дані основної Мавки. Для наступних TEST APK підпис може знову відрізнятися. Справжні облікові дані у TEST не вводь.

## Довгостроковий підпис
Для майбутніх оновлень під незмінним applicationId потрібно створити один постійний release-keystore та зберігати його і паролі тільки у захищених GitHub Actions Secrets, поза публічним репозиторієм. Без первісного ключа підпису Android не дозволить замінити вже встановлену версію. Новий постійний ключ НЕ оновить стару інсталяцію, якщо її підпис відрізнявся. Для перенесення даних знадобиться окремий механізм експорту й відновлення.

## Перевірка дизайну та іконок
У TEST відкрий Майно → Перевірити іконки (демо). Вісім зразків показують затверджені іконки, але не створюють надходжень і не змінюють залишки. Перевір верхню панель, чотири нижні вкладки, клавіатуру, поворот екрана.

## Перевірка двох ключів та Gmail (тільки тестові дані)
1. Створи тестовий профіль і збережи ClientId із меню профілю.
2. Збережи пароль документа один раз у Налаштування → Пароль документів. 090699 можна використати лише для тесту: це слабкий відомий пароль.
3. На ПК з .NET 10 у tools/MavkaEncrypt створи два окремі випадкові ключі командою create-key і парольний пакет командою package, передавши ClientId тестового профілю та generation=1.
4. Надішли пакет JSON зі встановленої адреси ГОЛОВНОЇ МАВКИ як вкладення із темою MAVKA_KEY_PACKAGE_V1.
5. На телефоні онови Вхідні, перевір Ключі обміну: відобразяться ідентифікатори поточного й майбутнього ключів, а не самі секрети.
6. Повторне читання того самого листа не повинно змінити покоління ключів; наступна ротація має застосувати попередній майбутній ключ як поточний.
7. Після установки ключів перевір відправлення службового тестового листа: вкладення має формат MAVKA_ENCRYPTED_V1.

Увага: поточна перевірка лише адреси Gmail From не є криптографічним підтвердженням походження першого пакета ключів. Не використовуй цей тест із конфіденційними матеріалами. Ніколи не надсилай ключі чи паролі у чат, GitHub issues або скріншоти.
